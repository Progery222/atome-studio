# Atome Studio — Бизнес-аналитик

Скилл для работы с требованиями и документацией проекта Atome Studio.

## Контекст проекта

**Atome Studio** — веб-платформа мониторинга и визуализации сервисов из множества внешних платформ. Сервисы отображаются как атомы в интерактивной космической визуализации.

Основное ТЗ: `tz_atom_studio.md`

## Принципы работы с требованиями

1. **Всегда сверяйся с ТЗ** — прочитай `tz_atom_studio.md` перед работой
2. **Используй ID-нумерацию** — FR-X.X для функциональных, NFR-X для нефункциональных, US-X.X для user stories
3. **Указывай приоритет** — P0 (must have), P1 (should have), P2 (nice to have), P3 (future)
4. **Пиши acceptance criteria** — для каждой user story

## Формат User Story

```markdown
| ID | User Story | Acceptance Criteria |
|----|-----------|-------------------|
| US-X.X | Как **[роль]**, я хочу [действие], чтобы [цель] | [Конкретные проверяемые критерии] |
```

## Формат функционального требования

```markdown
| ID | Требование | Приоритет |
|----|-----------|-----------|
| FR-X.X | [Описание требования] | P0/P1/P2/P3 |
```

## Предметная область

### Ключевые сущности
- **User** — пользователь системы
- **Workspace** — рабочее пространство команды
- **PlatformConnection** — подключение к внешней платформе
- **Service** — отдельный сервис/ресурс из подключённой платформы
- **Alert** — уведомление о событии

### Поддерживаемые платформы
- Cloudflare (Workers, Pages, DNS)
- PostHog (Dashboards, Insights)
- Postman (Collections, Monitors)

## Алгоритм работы

1. Прочитай текущее ТЗ (`tz_atom_studio.md`)
2. Определи, к какому разделу относится задача
3. Используй существующую нумерацию ID
4. Добавь/измени требование в нужном формате
5. Обнови acceptance criteria при необходимости
6. Проверь, нет ли конфликтов с существующими требованиями
