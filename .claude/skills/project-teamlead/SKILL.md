# Atome Studio — Тимлид / Планирование

Скилл для планирования и координации работы над проектом Atome Studio.

## Фазы проекта

| Фаза | Содержание | Статус |
|------|-----------|--------|
| MVP (4–6 нед.) | SPA + API + 3 интеграции + визуализация | В работе |
| Улучшения (3–4 нед.) | WebSocket, алерты, OAuth, метрики | Запланировано |
| Команды (3–4 нед.) | Multi-workspace, роли, нотификации | Запланировано |
| Полировка (2–3 нед.) | Адаптивность, performance, документация | Запланировано |

## Эпики MVP

| Эпик | Задачи | Зависимости |
|------|--------|-------------|
| E1: Инициализация | Monorepo, Docker, CI/CD, структура | — |
| E2: Auth | Регистрация, логин, JWT, guards | E1 |
| E3: Workspaces | CRUD workspace, модель данных | E2 |
| E4: Platform Adapters | Cloudflare, PostHog, Postman | E1 |
| E5: Services & Polling | Сущность Service, BullMQ polling | E3, E4 |
| E6: Frontend SPA | React app, роутинг, layout | E1 |
| E7: Canvas Visualization | Рефакторинг прототипа → модули | E6 |
| E8: Dashboard | Интеграция Canvas + Panel + API | E5, E7 |
| E9: Settings UI | Управление подключениями | E5, E6 |

## Оценка задач

| Размер | Story Points | Описание |
|--------|-------------|----------|
| S | 1 | Мелкая задача (< 2 часов) |
| M | 3 | Средняя (2–6 часов) |
| L | 5 | Большая (1–2 дня) |
| XL | 8 | Очень большая (2–3 дня), разбить если можно |

## Распределение задач по ролям

| Задача | Исполнитель |
|--------|------------|
| Monorepo setup, Docker, CI/CD | DevOps |
| Auth модуль, API endpoints | Backend |
| Platform adapters | Backend |
| BullMQ polling, WebSocket | Backend |
| React SPA, компоненты | Frontend |
| Canvas рефакторинг | Frontend |
| Дизайн-система, стили | UI/UX + Frontend |
| Тест-планы, автотесты | QA |
| Приоритизация, review | Teamlead |

## Формат задачи

```markdown
### [EPIC-ID] Название задачи

**Размер**: S/M/L/XL
**Роль**: Backend / Frontend / DevOps / QA
**Зависимости**: [что должно быть готово]
**Acceptance Criteria**:
- [ ] Критерий 1
- [ ] Критерий 2

**Описание**:
[Детали реализации]
```

## Definition of Done (общее)

- [ ] Код написан и работает
- [ ] Тесты написаны и проходят
- [ ] Code review пройден
- [ ] Нет lint-ошибок
- [ ] Документация обновлена (если API)
- [ ] Проверено на staging (если UI)
