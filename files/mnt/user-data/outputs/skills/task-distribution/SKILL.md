# Task Distribution Skill

Скилл для правильного распределения задач по ролям в IT-команде.

## Принципы распределения задач

1. **Читай описание роли** из `it-team/references/<роль>.md` перед назначением
2. **Учитывай зоны ответственности** — не дублируй задачи между ролями
3. **Проверяй зависимости** — некоторые задачи блокируют другие
4. **Оценивай нагрузку** — не перегружай одного участника

## Карта задач по ролям

### Фаза 1: Инициация проекта
| Задача | Роль |
|--------|------|
| Сбор требований от клиента | Бизнес-аналитик + Менеджер |
| Оценка технических рисков | Тимлид + DevOps |
| Составление роадмапа | Менеджер |
| Формирование технического задания | Бизнес-аналитик |

### Фаза 2: Дизайн
| Задача | Роль |
|--------|------|
| UX-исследование | UI/UX Дизайнер |
| Wireframes и прототипы | UI/UX Дизайнер |
| Валидация с бизнесом | Бизнес-аналитик |
| Создание Design System | UI/UX Дизайнер |

### Фаза 3: Разработка
| Задача | Роль |
|--------|------|
| Настройка инфраструктуры | DevOps |
| Разработка API | Бэкенд |
| БД и миграции | Бэкенд |
| Вёрстка компонентов | Фронтенд |
| Интеграция с API | Фронтенд |
| Планирование спринтов | Тимлид + Менеджер |

### Фаза 4: Тестирование
| Задача | Роль |
|--------|------|
| Написание тест-кейсов | QA |
| Функциональное тестирование | QA |
| Нагрузочное тестирование | QA + DevOps |
| Исправление багов | Разработчики (Front/Back) |

### Фаза 5: Релиз
| Задача | Роль |
|--------|------|
| Деплой на продакшн | DevOps |
| Smoke-тестирование после деплоя | QA |
| Release notes | Технический писатель |
| Уведомление клиента | Менеджер + Сейлз |

## Шаблон RACI-матрицы

При создании RACI используй:
- **R** (Responsible) — кто выполняет задачу
- **A** (Accountable) — кто несёт ответственность за результат
- **C** (Consulted) — кого консультируют
- **I** (Informed) — кого информируют

## Алгоритм распределения задач

1. Получи список задач
2. Для каждой задачи определи тип (UI, логика, инфра, документация и т.д.)
3. Назначь роль из карты выше
4. Укажи зависимости (что должно быть готово раньше)
5. Оцени сложность (S/M/L или story points)
6. Выяви блокеры
