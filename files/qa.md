# QA Инженер (Тестировщик)

## Зона ответственности
Проверяет продукт на ошибки, обеспечивает стабильность и соответствие требованиям.

## Ключевые задачи
- Ручное и автоматизированное тестирование
- Выявление багов и дефектов
- Проверка соответствия продукта требованиям
- Тестирование безопасности и производительности
- Документирование найденных ошибок
- Контроль исправления дефектов

## Взаимодействие с другими ролями
- **Разработчики**: сообщает о багах, проверяет исправления
- **Тимлид**: согласует приоритеты тестирования
- **Менеджер**: предоставляет отчёты о качестве
- **Дизайнер**: проверяет соответствие реализации макетам

## Виды тестирования
| Тип | Описание |
|-----|----------|
| Функциональное | Проверка соответствия требованиям |
| Регрессионное | Проверка, что новое не сломало старое |
| Нагрузочное | Поведение при высоких нагрузках |
| Безопасность | Уязвимости, SQL-инъекции, XSS |
| Usability | Удобство использования |
| API-тестирование | Проверка эндпоинтов (Postman) |

## Инструменты
- Ручное: TestRail, Zephyr, Jira
- Автоматизация: Selenium, Cypress, Playwright
- API: Postman, RestAssured
- Нагрузка: JMeter, k6
- Мобильное: Appium

## Уровни компетенций
| Уровень | Что умеет |
|---------|-----------|
| Junior | Ручное тестирование, написание тест-кейсов |
| Middle | Автотесты, API-тестирование, работа с CI |
| Senior | Стратегия тестирования, фреймворки, менторинг |

## Типичные задачи на проекте
- [ ] Написание тест-планов и тест-кейсов
- [ ] Регрессионное тестирование перед релизом
- [ ] Заведение багов в трекере (Jira)
- [ ] Проверка исправленных багов
- [ ] Написание автотестов
- [ ] Участие в code review тестов

## Definition of Done (что значит "задача готова")
- Тест-кейсы написаны и пройдены
- Критические баги исправлены
- Регрессия пройдена
- Документация обновлена
