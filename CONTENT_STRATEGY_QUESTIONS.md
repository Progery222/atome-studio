# Atome Studio — Вопросы для детального планирования
> Дата: 2026-04-08 | Статус: требует ответов перед началом реализации

---

## Контекст

Уже работают два сервиса:
- **SportZavod** — спортивные новости → HeyGen аватар → TikTok
- **content-zavod** — любая тема → Kling/Kie.ai видео → TikTok

Цель: расширить платформу для американской аудитории, добавить нарезку роликов, масштабировать на других пользователей (SaaS).

## Блок 2 — Нарезчик роликов (clip-zavod)

> **Идея сервиса:** Принимает длинное видео (YouTube ссылка или файл) → нарезает на 5–15 коротких клипов с субтитрами, 9:16 формат → загружает в MinIO → ставит в очередь публикации.

- [ ] Откуда будет браться исходное видео?
  - a) Ссылка на YouTube (yt-dlp)
  - b) Загрузка файла через UI
  - c) Автоматически из RSS-фидов подкастов/стримов
  - d) Все варианты
- [ ] Какая максимальная длина входного видео? (30 мин / 1 час / 3 часа / без ограничений)
- [ ] Нужна ли загрузка из других источников? (Rumble, Twitch VOD, собственный сервер)

### 2.2 Логика определения клипов

> **Важный выбор — как определять "хорошие" моменты:**

- [ ] **Вариант A (простой):** PySceneDetect — режет по смене сцен/переходам. Быстро, без AI, не учитывает смысл.
- [ ] **Вариант B (умный):** Whisper транскрипция → LLM анализ → определение высокоэнергичных, смешных, ценных моментов по тексту. Медленнее (~2-5 мин/час видео на GPU), лучше качество.
- [ ] **Вариант C (гибридный):** Сначала PySceneDetect отсекает тишину/статичные сцены, потом LLM выбирает лучшее из остатка.
- [ ] Какой вариант предпочесть?

- [ ] Нужен ли ручной ревью клипов в UI перед публикацией или полностью авто?
- [ ] Сколько клипов нужно из одного длинного видео? (5 / 10 / 20 / настраиваемо)
- [ ] Минимальная и максимальная длина одного клипа? (рекомендация: 30–90 сек для Creator Rewards)

### 2.3 Обработка видео

- [ ] Нужен ли reframe 16:9 → 9:16 с отслеживанием спикера (face tracking)?
  - Это требует Computer Vision (MediaPipe/InsightFace) — добавляет сложность
  - Альтернатива: простой center crop без face tracking
- [ ] Нужны ли burned-in субтитры? (Whisper → SRT → FFmpeg hardcode)
- [ ] Нужна ли фоновая музыка (тихая, под субтитры)?
- [ ] Нужно ли добавлять intro/outro (логотип, призыв к действию) к каждому клипу?
- [ ] Какой видеокодек для выхода? (H.264 совместим везде; H.265 меньше размер но медленнее encode)

### 2.4 Инфраструктура clip-zavod

  - a) Railway (CPU only — транскрипция будет медленная, ~10-20 мин/час видео)

## Блок 4 — Массовая генерация

> **Текущая ситуация:** Генерация запускается вручную через UI на странице /generate. Для масштаба нужна автоматическая массовая генерация.

### 4.1 Что такое "массовая генерация" для вас?

- [ ] Вариант A: Одна кнопка "запустить всё" — автоматически генерирует контент для всех активных аккаунтов на день
- [ ] Вариант B: Расписание — каждый день в 7:00 UTC автоматически запускается генерация на весь парк аккаунтов
- [ ] Вариант C: Очередь — задаёшь план на неделю, сервис сам разбивает по дням/часам с учётом лимитов

### 4.2 Масштаб

- [ ] Сколько аккаунтов будет в системе? (10 / 50 / 100 / 500+)
- [ ] Сколько видео нужно генерировать в день? (50 / 200 / 500 / 1000+)
- [ ] Бюджет на генерацию в день? (помогает выбрать провайдера и количество)

### 4.3 Технические лимиты для массовой генерации

> **Ключевые ограничения которые нужно обойти:**

| Сервис | Лимит | Решение |
|--------|-------|---------|
| HeyGen | 100 приоритетных видео/мес, затем 2–36ч ожидания | Несколько HeyGen аккаунтов / перейти на D-ID |
| Kling API | Нет жёсткого лимита, но $0.08/видео | Параллельные очереди, batch processing |
| OpenAI GPT-4o (скрипты) | Rate limit по токенам/мин | Retry + backoff + несколько API ключей |
| TikTok posting | 15 видео/день на аккаунт | Device farm (уже есть) |
| TikTok perceptual hash | Одинаковые видео банятся | Micro re-encode каждого файла перед постингом |

- [ ] Сколько HeyGen аккаунтов сейчас? Достаточно ли приоритетной квоты?
- [ ] Нужен ли переход с HeyGen на D-ID для массового производства (D-ID дешевле при больших объёмах)?
- [ ] Нужна ли дедупликация видео (micro re-encode) перед загрузкой на каждый аккаунт?

### 4.4 Ограничения браузерной автоматизации

> **Вывод из исследования:** Playwright/Selenium для TikTok не работает в 2026 — мгновенные баны.

## Блок 6 — clip-zavod технические детали

> **Минимальная реализация сервиса нарезки:**

### 6.1 Что такое MVP clip-zavod

Предлагаемый минимальный функционал:
1. Принимает YouTube URL или файл
2. Скачивает через yt-dlp (для YouTube)
3. Транскрибирует через faster-whisper
4. LLM (GPT-4o-mini) выбирает топ-10 моментов из транскрипта
5. FFmpeg нарезает, center-crop до 9:16, burn-in субтитры
6. Загружает клипы в MinIO (`clip-zavod/{date}/{source_slug}/{clip_N}.mp4`)
7. Возвращает список клипов через REST API для dashboard

- [ ] Этот MVP достаточен для старта? Или нужен face tracking сразу?
- [ ] Нужен ли просмотр клипов прямо в UI перед публикацией?
- [ ] Нужна ли интеграция с queue (Orchestrator) сразу, или сначала просто генерация/хранение?

### 6.2 Ограничения YouTube download

- [ ] YouTube Terms of Service запрещают массовое скачивание. Это допустимо для вашего use case (личный/внутренний инструмент)?
- [ ] Нужна ли поддержка других источников без ограничений (загрузка собственных файлов, Cloudflare Stream)?

## Приложение: Рекомендации по описанию задач

### Как описывать задачи в PROGRESS.md чтобы работать автономно

**Плохо (слишком размыто):**
```
- [ ] Добавить нарезку видео
```

**Хорошо (конкретно и проверяемо):**
```
- [ ] 1.1 clip-zavod: FastAPI сервис с POST /api/clip { url, max_clips, min_duration, max_duration } 
      → скачивает через yt-dlp, транскрибирует faster-whisper base, 
      → возвращает job_id — 🧪 `curl -X POST .../api/clip -d '{"url":"...", "max_clips":5}'`
- [ ] 1.2 clip-zavod: LLM highlight scorer — GPT-4o-mini анализирует транскрипт, 
      возвращает List[{start, end, score, reason}] топ-10 моментов 
      → 🧪 pytest tests/test_scorer.py
- [ ] 1.3 clip-zavod: FFmpeg pipeline — center crop 9:16, burn-in субтитры (SRT → ass), 
      encode H.264 CRF 23 — 🧪 output в /tmp/clips/ минимум 3 файла
```

### Обязательные элементы каждого шага PROGRESS.md:

1. **Чёткий входной контракт** — что принимает (API endpoint, параметры, форматы)
2. **Чёткий выходной контракт** — что возвращает (JSON схема, файлы, события)
3. **Проверочная команда** (`🧪 pytest` / `curl` / `tsc --noEmit`) — с ненулевым exit code при ошибке
4. **Атомарность** — один шаг = одна изолированная задача, которую можно протестировать независимо

### Шаблон для нового сервиса (завода):

```markdown
## Сервис: {name}-zavod

### Стек
- Python 3.11, FastAPI, {зависимости}
- Деплой: Railway, порт {N}

### Фаза 1 — Core Pipeline
- [ ] 1.1 {service}: {входной контракт} → {выходной контракт} — 🧪 `{команда}`
- [ ] 1.2 {service}: {входной контракт} → {выходной контракт} — 🧪 `{команда}`

### Фаза 2 — Интеграция с Dashboard
- [ ] 2.1 Dashboard API: адаптер {name}zavodAdapter → `GET /health`, `GET /api/jobs`, `POST /api/clip`
- [ ] 2.2 Dashboard UI: страница /{name} — форма запуска + список jobs
- [ ] 2.3 shared types: {NewJobType}, {NewResultType} в packages/shared/src/index.ts
```
