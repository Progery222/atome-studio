# ТЗ: Atomic Service Dashboard
> Визуальный дашборд мониторинга сервисов в стиле атомарной модели

---

## 🧠 Общая идея

Создать **веб-приложение на Vanilla JS + Three.js**, которое визуализирует работу микросервисов в виде атомарной/планетарной 3D-модели. Главная страница — «галактика сервисов», при клике на каждый «атом» — провал внутрь сервиса с визуализацией его внутренних процессов и метриками.

---

## 🛠 Стек технологий

| Слой | Технология | Зачем |
|------|------------|-------|
| Рендеринг 3D | **Three.js** | Атомы, орбиты, частицы, анимации |
| Язык | **Vanilla JS (ES Modules)** | Лёгкий, без фреймворка, просто масштабировать |
| Сборка | **Vite** | Быстрый dev-сервер, hot reload |
| Данные | **Собственный REST/WebSocket API** | Метрики сервисов в реальном времени |
| Конфиг | **JSON-файлы** | Описание сервисов, процессов, дашбордов |
| IDE | **VS Code / Cursor** | Основная среда разработки |

### MCP-инструменты для вайбкодинга в IDE

Для быстрой разработки и тестирования подключи следующие MCP-серверы:

- **Cloudflare MCP** — деплой прямо из чата, Workers для API-прокси метрик
- **Postman MCP** — тестирование API сервисов не выходя из IDE
- **PostHog MCP** — если захочешь добавить аналитику поведения пользователей
- **Amplitude MCP** — опционально, для дополнительных метрик

> Claude Code сам поднимает dev-сервер, правит Three.js сцену по описанию на русском,
> а MCP-серверы дают прямой доступ к внешним инструментам без выхода из терминала.

## 🖥 Экран 1 — Главная страница «Галактика сервисов»

### Что видит пользователь

- Тёмный космический фон с частицами (звёзды)
- В центре — **главный атом** (ядро системы), медленно вращается
- Вокруг него по орбитам летают **атомы-сервисы** (по одному на каждый сервис из конфига)
- Количество атомов = количество подключённых сервисов (динамически)
- Между атомами периодически пробегают **световые лучи** (имитация трафика)
- По периметру или в углах — **мини-дашборды**: общий upttime, суммарный RPS, количество ошибок и т.д.

### Поведение

- При **наведении** на атом — он подсвечивается, появляется тултип с именем сервиса и кратким статусом
- При **клике** — плавный zoom-in в этот атом → переход на Экран 2

### Технические детали

- `GalaxyScene.js` создаёт Three.js сцену
- Данные о сервисах загружаются из `services.json` через `configLoader.js`
- Статус каждого сервиса (online/offline/degraded) приходит из API каждые N секунд
- Цвет атома меняется в зависимости от статуса: зелёный / жёлтый / красный

## 🔬 Экран 2 — Внутренняя страница сервиса

### Что видит пользователь

- В центре — **ядро сервиса** (большой светящийся атом)
- Вокруг него по орбитам летают **атомы-процессы** (receive → validate → store → …)
- Количество процессов берётся из конфига конкретного сервиса
- Между ядром и процессами летают частицы (данные в обработке)
- Вокруг сцены расположены **дашборды с метриками** (тоже из конфига)

### Дашборды метрик

Каждый дашборд — отдельный `<div>` поверх Three.js canvas (CSS overlay):

| Тип | Описание |
|-----|----------|
| `line` | Линейный график, например RPS по времени |
| `bar` | Столбчатый — например распределение ошибок |
| `gauge` | Спидометр — latency, CPU |
| `counter` | Просто большое число — кол-во обработанных событий |
| `status` | Цветной индикатор + текст |

- Количество дашбордов и метрик — настраивается в `services.json` для каждого сервиса
- Данные обновляются через WebSocket или polling к твоему API

### Поведение

- Кнопка «Назад» / клик на пустую область — zoom-out обратно на главную
- Активный процесс (тот, в котором сейчас обрабатываются данные) **пульсирует** ярче

## 🔌 API — Формат данных от бэкенда

Твой бэкенд должен отдавать данные в таком виде:

### `GET /api/services` — список сервисов со статусами
```json
[
  { "id": "data-ingestion", "status": "online", "uptime": 99.8 },
  { "id": "ml-pipeline",    "status": "degraded", "uptime": 97.1 }
]
```

### `GET /api/metrics/:serviceId` — метрики конкретного сервиса
```json
{
  "requests_per_second": 142,
  "error_rate": 0.02,
  "avg_latency_ms": 38,
  "processed_total": 1043200
}
```

### `WS /ws/metrics` — WebSocket для real-time (опционально)
```json
{ "serviceId": "data-ingestion", "metric": "requests_per_second", "value": 148, "ts": 1711540000 }
```

## 🚀 Как вайбкодить с Claude Code

1. Открой проект в Cursor / VS Code с Claude Code
2. Подключи MCP-серверы: Cloudflare + Postman (через `.mcp.json` в корне проекта)
3. Запусти `vite` — dev-сервер на `localhost:5173`
4. Пиши Claude Code задачи типа:
   - *«Добавь новый атом-сервис с 4 орбитами и линейным дашбордом latency»*
   - *«Сделай чтобы атом мигал красным если error_rate > 5%»*
   - *«Протестируй API /api/metrics/data-ingestion через Postman MCP»*
5. Cloudflare MCP деплоит воркер-прокси для твоего API если нужен CORS или авторизация
